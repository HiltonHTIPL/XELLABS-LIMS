 3. KNOWN ISSUE #1 — NODE_ENV must be "production" in the server .env
--------------------------------------------------------------------------------
 SYMPTOM : Frontend container crash-loops. Build fails with:
             TypeError: Cannot read properties of null (reading 'useContext')
             Error occurred prerendering page "/_global-error" (or /_not-found)
           And this warning appears in the log:
             "You are using a non-standard NODE_ENV value"

 CAUSE   : /home/hephzibahtech2/xellabs-lims/.env contained NODE_ENV=development.
           Compose injects it into the frontend container, and `next build`
           under development mode loads mismatched React bundles -> the
           useContext crash on Next's internal pages. Works locally because
           local .env never sets NODE_ENV.

 FIX     : In the server's project-root .env:
             NODE_ENV=production
           (or delete the NODE_ENV line entirely — compose defaults to
           production). Then recreate the frontend:
             docker compose -f docker-compose.yml -f docker-compose.server.yml \
               up -d --no-build --force-recreate frontend

 CHECK BEFORE EVERY DEPLOY:
   grep NODE_ENV /home/hephzibahtech2/xellabs-lims/.env
   -> must print NODE_ENV=production (or nothing)

 6. KNOWN ISSUE #4 — builds hang / containers stuck at "Created"
--------------------------------------------------------------------------------
 The box is shared (dataxpulse, superset, senaite-original, rmt-blazor...)
 and has NO SWAP configured with ~8GB RAM. Under load, docker builds can
 hang, and interrupted compose runs leave containers stuck in "Created".

 IF A BUILD HANGS:
   - Check for stray processes:  ps aux | grep -E 'buildx|compose'
   - Check disk:                 df -h /   (build cache piles up: docker
                                 buildkit GC will churn the disk when full)
   - Stuck "Created" containers: docker rm -f <name> then re-run compose up
   - The docker daemon itself is fine if `docker run --rm hello-world` works.

 RECOMMENDED ONE-TIME FIX (needs sudo): add 4GB swap
   sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
   sudo mkswap /swapfile && sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
