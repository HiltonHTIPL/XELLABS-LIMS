Design Principle Application Log
=================================
Per CLAUDE.md Section 22/23. Append one row per feature after implementation.
Format: Feature | Pattern applied | How

Master Data Import — Instruments/Storage Locations (2026-07-07) | DRY + Adapter Pattern | core/excel_import.py's read_excel_rows() and core/senaite_service.py's import_instrument_row/import_storage_location_row/delete_object are shared verbatim between the Django management commands and the API views — one place owns "how to parse an import sheet" and "how to talk to SENAITE for this operation", not duplicated per entry point.

Duplicate-detection on re-import (2026-07-07) | Single Source of Truth | _find_active_by_title() + per-field exact-match comparison (_instrument_matches()) is the one place that decides "is this a duplicate" — used identically by both Instrument and Storage Location import paths, and correctly excludes soft-deleted (inactive) records without a separate code path.

SENAITE error sanitization (2026-07-07) | Adapter Pattern (isolate SENAITE-specific detail from the UI boundary) | _sanitize_error() in core/senaite_service.py strips SENAITE hostnames/product name from any exception string before it can reach an API response — one chokepoint enforcing the Section 17b white-label rule, rather than sanitizing at every call site.

Report generation failure handling (2026-07-08) | Explicit State Modeling / Single Source of Truth | Added a real "failed" status to Report.STATUS and had the Celery task set it once retries are exhausted, instead of leaving the frontend to infer failure from a stuck "draft" status via a polling timeout. The backend DB row is now the one source of truth for whether generation succeeded, failed, or is still running.

Report generation UI timeout (2026-07-08) | KISS | Frontend keeps a simple hard 120s polling timeout as a defensive backstop against any future silent-hang bug, rather than building a more complex retry/backoff state machine — a plain timer plus a retry button covers the real failure mode without extra ceremony.

Report generation efficiency — 5 fixes (2026-07-08) | N+1 elimination + Adapter Pattern + Fail-fast + Dedicated Queue | (1) Specs for all worksheet-assignment rows fetched in a single bulk query instead of one query per row — classic N+1 fix. (2) Server-side push (reporting/views.py ReportViewSet.stream, an NDJSON adapter matching the same pattern already used by Master Data Import) replaces the frontend's 3s setInterval polling — one chokepoint owns "how the client learns about status changes" instead of duplicating polling logic per feature. (3) NON_RETRYABLE_EXCEPTIONS makes the Celery task fail fast on errors that can never succeed on retry (schema/template bugs), instead of always retrying 3×30s regardless of error type. (4) Dedicated `celery-reports` queue/worker isolates report generation from the 5-minute cross-tenant SENAITE sync sweep on the main worker — Strategy-like separation of concerns between "fast interactive work" and "slow periodic sync work" so one never blocks the other.

Frontend gap-filling for 9 Django subsystems (2026-07-08) | Feature-Based Architecture + DRY + Adapter Pattern + Separation of Concerns | Each new area (Audit Trail, Approvals, QC, Inventory, Instrument Maintenance, Tenants, Tasks, Specifications, Results) got its own `app/dashboard/<feature>/` directory with `page.tsx` + `_components/`, matching every existing page — no shared "god folder". Structurally-identical areas (Inventory items, Instrument Calibration/Maintenance/Runs/Result-Imports) were built as ONE tabbed page + shared table/modal shape each, rather than 3-4 near-duplicate pages, to avoid copy-pasted CRUD boilerplate. Every new area got its own `app/actions/<domain>.ts` wrapping `djangoFetch`, isolating the HTTP/pagination-unwrapping detail from the UI components exactly like every existing action file. Server actions handle data only; `*Shell.tsx` client components handle UI/interaction only — same split as the rest of the codebase, applied consistently across all 9 new areas rather than improvising a new structure per feature.
